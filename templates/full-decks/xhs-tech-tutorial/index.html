Agent万能公式和5种新手类型

Agent公式和实例
Agent = Role + Goal + Tools + Rules + Output
目标是什么Agent要产出什么成果
需要什么信息网页搜索、文件、数据库、还是用户消息
允许做什么搜索、编辑、发邮件、写代码、调API
必须遵守什么语气、格式、安全规则、不确定时怎么办
Example
Role：加密货币研究助手
Goal：找到准确信息并清晰总结
Tools：网页搜索、文件搜索、计算器
Rules：引用来源、不猜测、标注不确定性
Output：摘要 + 风险 + 机会 + 最终判断

Agent的核心引擎

核心循环
插图：核心循环图
所有Agent共享同一个核心循环
用户输入 → LLM推理 → 决策：回复还是调用工具
如果调用工具 → 执行 → 结果反馈回LLM → 继续循环
LLM = 大脑
负责推理和决策
Tools = 双手
执行搜索、计算、文件读写
Memory = 笔记本
记录对话历史和上下文
增强型LLM三大能力

工具调用

让模型调用外部函数
计算器、数据库、API、文件操作

信息检索

从外部拉取相关信息
搜索引擎、文档库、向量数据库

记忆存储

跨轮对话保持上下文
消息历史、持久化存储

Workflow vs Agent
插图
Workflow 确定性执行
代码控制流程，相同输入相同路径
成本低，适合步骤固定的任务
插图
Agent 动态决策
LLM自主决定下一步
灵活但成本高，适合开放性任务
起步建议：先用Workflow，搞不定再升级成Agent

五种核心工作流模式

插图
Prompt Chaining 提示链
任务拆成多步串联执行，每步处理上一步输出
中间加质检门控验证质量
适合可清晰拆分的固定子任务
插图
Routing 路由分发
先分类，再派给专属处理器
每类路由到专用prompt处理
适合不同类别需要完全不同处理逻辑
插图
Parallelisation 并行处理
多路并发，最后汇总结果
切分法：独立子任务同时处理
适合子任务互不依赖或需要高置信决策
插图
Orchestrator-Workers 指挥执行
中枢动态派活，子任务运行时决定
不是预设的固定分工，是实时调度
适合无法预测结构的复杂任务
插图
Evaluator-Optimiser 评估优化
一个生成，一个评审，循环改进
不合格就打回重做，直到达标
适合有明确质量标准的迭代任务

记忆系统三选一

两种记忆类型
插图
短期记忆
短期记忆 = 对话历史
就是到目前为止聊了什么，默认就有
插图
长期记忆
长期记忆 = 外部知识库
你的笔记、PDF、文档、数据库，需要额外配置
三条路怎么选

选项A 不加记忆

70%的场景够用
适合大多数新手
不需要跨对话记住东西就不要加

选项B 对话记忆

SDK已内置
大部分框架自动处理
不重置消息列表就行

选项C 文件记忆 RAG

上传文档加文件搜索工具
比自建向量数据库简单得多
适合需要查阅大量文档的场景

大多数选A 需要上下文选B 需要查文档选C
插图
过度设计警告
还没确认是否需要记忆就急着加向量数据库
还没测试简单方案就搭复杂embedding流水线
铁律：Agent没有记忆也能跑就不要加

Evaluator生成+评审循环有明确质量标准的迭代任务
