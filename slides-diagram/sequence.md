# Sequence Diagram（时序图）

用于展示多个参与方在时间轴上的消息交互序列，按时间从上到下依次发生。

## 适用场景

| 场景 | 示例 |
|------|------|
| API 调用链 | 客户端 → API Gateway → Service → DB 的单次请求 |
| 微服务间通信 | 同步 RPC、异步消息、回调的完整交互 |
| 认证流程 | Login → OAuth → Token 验证 → 资源访问 |
| 分布式事务 | 2PC、Saga、TCC 的参与方交互 |
| 端云协同 | 端侧推理请求 → 云端模型服务 → 特征补全 → 结果返回 |

## 典型视觉结构

| 元素 | SVG 形状 | 说明 |
|------|---------|------|
| 参与者头 | `<rect>` 顶部方框 | 标注角色名称（Client、Server、DB） |
| 生命线 | `<line>` 垂直虚线 | 从参与者头向下贯穿全图 |
| 激活框 | `<rect>` 窄矩形 | 叠加在生命线上，表示该参与方正在处理 |
| 同步消息 | `<line>` 实线 + 实心箭头 | 调用方等待返回（blocking call） |
| 异步消息 | `<line>` 实线 + 开放箭头 | 调用方不等待（non-blocking） |
| 返回消息 | `<line>` 虚线 + 开放箭头 | 返回值或确认 |
| 自调用 | 弯曲箭头回自身 | 同一参与方的内部方法调用 |
| 注释框 | `<rect>` 折角 | 对某条消息的补充说明 |

## 布局模式

```
【基本时序图】
   Client          Service         Database
     │                │                │
     ├─── Request ───▶│                │
     │                ├─── Query ─────▶│
     │                │                │
     │                │◄── Result ─────┤
     │◄── Response ───┤                │
     │                │                │
     ▼                ▼                ▼
   (时间自上而下)
```

## z-order 分层规则

```
Layer 1: 背景 (Background)
  └── 深色画布填充 (#0f172a)

Layer 2: 生命线 (Lifelines)
  └── 每个参与者的垂直虚线
  └── 从参与者头底部扩展至画布底部

Layer 3: 激活框 (Activation Boxes)
  └── 沿生命线放置的窄矩形（宽约 10-14px）
  └── 表示该参与者正在处理请求的时间段

Layer 4: 消息箭头 (Message Arrows)
  └── 两个生命线之间的水平箭头
  └── 同步 = 实线 + 实心箭头
  └── 异步 = 实线 + 开放箭头
  └── 返回 = 虚线 + 开放箭头
  └── 自调用 = 弯曲箭头

Layer 5: 文本标注 (Text Labels)
  └── 消息名称（沿箭头上方或左侧标注）
  └── 参数/协议（小字号，可选）
  └── 序号（每条消息左侧编号 1, 2, 3...）

Layer 6: 参与者头 (Participant Headers)
  └── 顶部方框，填充色区分角色
  └── 角色名称居中，粗体

Layer 7: 标题 (Title)
  └── 左上角或顶部居中
```

## 消息类型标注

| 消息类型 | 箭头样式 | 线型 | 示例场景 |
|---------|---------|------|---------|
| 同步调用 | → (实心三角) | 实线 | HTTP POST、gRPC、RPC |
| 异步调用 | → (开放三角) | 实线 | Kafka 消息、异步任务提交 |
| 返回值 | → (开放三角) | 虚线 | 函数返回、Response |
| 回调 | → (开放三角) | 虚+实混合 | 异步回调、Webhook |
| 转发 | → (开放三角) | 实线 + `<<forward>>` 标注 | 代理转发 |

## 语义配色

| 元素 | 色号 | 说明 |
|------|------|------|
| 参与者头 | Primary (#60a5fa) | 主要调用方 |
| 参与者头（外部）| Accent (#f472b6) | 外部系统/第三方 |
| 参与者头（内部）| Secondary (#a78bfa) | 内部服务 |
| 激活框 | Primary (#60a5fa) 半透明 | 基于参与者色 |
| 同步消息 | Primary (#60a5fa) | 强调实时路径 |
| 异步消息 | Alert (#fb923c) | 区分异步路径 |
| 返回消息 | Connector (#94a3b8) | 降低视觉权重 |
| 生命线 | Connector (#94a3b8) | 灰色虚线 |

## 何时选择 Sequence Diagram

- **选择此类型**：需要精确展示"谁在什么时间点给谁发了什么消息"
- **不用此类型**：如果重点是系统组件结构而非交互时间线，用 Architecture；如果是简单业务流程无多参与方交互，用 Flowchart

## 与其他图型对比

| 对比项 | Sequence | Architecture | Flowchart | Structural |
|--------|:--------:|:-----------:|:---------:|:----------:|
| 时间轴 | 显式（Y 轴） | 无 | 隐式顺序 | 无 |
| 参与方 | 多角色头 | 组件名 | 无角色概念 | 层级标签 |
| 消息类型 | 细粒度区分 | 简单标注 | N/A | N/A |
| 激活/阻塞 | 可表达 | 不表达 | 不表达 | 不表达 |
