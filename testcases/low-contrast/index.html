为什么需要 Agent View

多 Agent 并行已成常态，但会话管理碎片化

痛点
会话分散，跟踪困难
修 bug、审 PR、分析日志往往同时启动多个会话。此前这些会话分散在不同终端窗口或 tmux 分屏中，跟踪状态和进度需反复切换。
解法
Agent View：一屏管理所有会话
在一个界面中调度和管理多个 Claude Code 会话——展示每个会话正在执行什么、哪些需要输入；后台会话不依附终端独立运行，随时可返回查看或接管。

四项核心能力

统一会话管理，四种方式掌控所有 Agent

01

会话列表与三态标识

所有活跃会话一览：working（执行中）、waiting on you（等待输入）、done（已完成）。无需切换窗口即可知晓全部状态。

02

Peek & Reply

按空格键展开最新回复预览，预览窗口支持直接输入文本回复。快速确认 Agent 输出，不打断当前任务。Esc 退出预览。

03

后台运行

通过 supervisor 进程托管后台会话，不依附任何终端窗口。会话持续执行，无需保持终端打开，随时可返回查看进度或重新接入。

04

无缝切换与会话隔离

按 Enter 进入完整会话深度交互，按 Esc 返回列表视图。每个会话拥有独立的文件编辑上下文，多会话并行时互不干扰。

三种调度方式

任意场景下都能快速启动后台 Agent

1
仪表板内直接输入
在 Agent View 界面中输入任务描述，回车即创建新会话并开始执行
2
会话内 /bg 命令
在任意活跃会话中输入 /bg "task"，将该任务作为独立后台会话启动
3
Shell 命令
在终端执行 claude --bg "task"，直接从 shell 创建后台 Agent 会话
三种入口进入仪表板：终端运行 claude agents / 任意会话按左方向键 / 会话内使用 /agents 命令

可用性与限制

研究预览版，功能持续迭代中

01

版本要求

Claude Code v2.1.139 及以上版本。可通过 claude --version 检查当前版本。

02

计划支持

Pro、Max、Team、Enterprise 及 API 计划均可使用。

03

配额消耗

每个 Agent View 会话独立消耗订阅配额，与普通会话规则相同。多会话并行时需注意总用量。

04

管理员设置

Team 和 Enterprise 计划管理员可通过 disableAgentView 设置在组织层面禁用该功能。

研究预览版说明：界面布局和快捷键可能在后续版本中调整或变更。

Agent View

不改变 Agent 的执行能力或输出质量，聚焦于多会话场景下的调度与管理
将分散在多个终端窗口中、依赖手动跟踪的会话，集中到一个可预览、可切换、可后台运行的统一界面。每个会话独立运行、独立消耗配额，通过 supervisor 进程托管实现不依附终端的后台执行。
