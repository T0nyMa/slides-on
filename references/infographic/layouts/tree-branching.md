# Tree Branching

**Best for**: Hierarchies, decision trees, taxonomies with depth, and branching structures
**Structure**: A root node at the top (or left) that branches downward (or rightward) through multiple levels, progressively splitting into finer categories or sub-nodes. Lines connect parent nodes to children
**Elements**: Root node, branch lines, intermediate nodes, leaf nodes, level indicators, branch labels

## Content Requirements
- A clear hierarchical relationship (single root, multiple levels)
- 2-4 branching levels
- Consistent branching logic at each level (e.g., all nodes at level 2 split by the same criterion)
- Leaf nodes should be the terminal elements of the hierarchy

## When to Use
- Organization charts and reporting structures
- Decision trees with clear branching logic
- Classification hierarchies (domain → phylum → class → ...)
- Feature tree or capability breakdown with parent-child relationships

## When NOT to Use
- Flat, non-hierarchical structures — use bento-grid
- Networks with cross-connections (not pure trees) — use hub-spoke
- When the hierarchy has many nodes at each level (becomes visually overwhelming)
