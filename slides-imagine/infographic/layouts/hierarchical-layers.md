# Hierarchical Layers

**Best for**: Layered architecture, tech stacks, and tiered system structures
**Structure**: Stacked horizontal layers (top to bottom or bottom to top), each representing a level of abstraction or a system layer. Layers are clearly labeled and may have annotations for inter-layer communication
**Elements**: Stacked horizontal bands, layer labels, inter-layer arrows or connectors, component icons within layers, layer descriptions

## Content Requirements
- 3-7 hierarchical layers with a clear ordering principle (abstraction level, dependency order)
- Each layer has a name and brief description of its responsibility
- Optional: components or technologies within each layer
- Optional: communication paths between adjacent layers

## When to Use
- Technology stack diagrams (frontend → backend → infrastructure)
- Network protocol layers (OSI model, TCP/IP stack)
- Organizational hierarchies with clear tiered structure
- Architecture diagrams with layered dependencies

## When NOT to Use
- Non-hierarchical groupings — use bento-grid or dense-modules
- Tree-like branching structures — use tree-branching
- When layers have complex cross-layer communication (not strictly stacked)
