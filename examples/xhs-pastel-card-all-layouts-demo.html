Why · 为什么

好的演讲系统，帮你做三件事

不是做不出漂亮的 slide，是每次都要重新做。

  • ① 统一设计语言

    所有页共用同一套 tokens，字号、颜色、阴影不会跑偏。

  • ② 降低复用成本

    下一次讲同类话题，复制 deck、换数据、换主题即可。

  • ③ 可切换，可演示

    按 T 即可循环切主题、按 A 可切动效，汇报现场加分。

Snippet · 运行时核心

按一下键盘就跑起来了

// runtime.js — keyboard-driven deck
function go(n) {
  n = Math.max(0, Math.min(total - 1, n));
  slides.forEach((s, i) => {
    s.classList.toggle('is-active', i === n);
  });
  idx = n;
  barFill.style.width = ((n+1)/total*100)+'%';
  history.replaceState(null, '', '#/'+(n+1));
}
document.addEventListener('keydown', (e) => {
  if (e.key === 'ArrowRight' || e.key === ' ') go(idx+1);
  if (e.key === 'ArrowLeft') go(idx-1);
  if (e.key === 't') cycleTheme();
});

Trade-offs · 诚实的取舍

纯 HTML 演讲：好在哪，痛在哪

✓ 好处

  • 零构建：一个文件就能跑
  • 可 diff：Git 友好
  • 可编程：动效自由定制
  • 可分发：URL/PDF/PNG

✗ 痛点

  • 协作不像 Keynote 实时
  • 非程序员上手稍陡
  • 复杂动效仍需写 JS
  • 离线字体可能缺失

Pattern

Pattern · 双栏

概念 ⟷ 示例

左栏 · 概念

一个主题 = 一组 CSS 变量。把颜色、字体、圆角、阴影全部收到 :root 里。

  • — tokens 定义语义
  • — base.css 用 tokens 排版
  • — 每个主题只改变量

右栏 · 示例

:root {
  --bg: #fff;
  --text-1: #0c0d10;
  --accent: #3b6cff;
  --radius: 18px;
}
.card {
  background: var(--bg);
  color: var(--text-1);
  border-radius: var(--radius);
}
