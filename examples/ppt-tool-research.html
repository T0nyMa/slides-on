cat html-ppt-skill/README.md

html-ppt-skill

定位：纯 HTML/CSS/JS 的演示文稿系统，生成可交互的网页演示。

渲染引擎
纯静态 HTML + CSS Variables + 原生 JS，零框架依赖
主题系统
36 个内置主题，基于 CSS Variables 实现，切换主题只需替换 :root 变量
布局系统
31 种布局类型，每种对应 templates/single-page/*.html 模板
动画系统
27 种 CSS 动画 + 20 种 Canvas 特效，通过 data-anim 属性声明
导航机制
runtime.js（~960行）管理幻灯片状态，URL #/N 深链接，键盘事件
Presenter 模式
window.open() 弹窗 + iframe 预览，BroadcastChannel 双向同步
+ 优势
完全可交互的演示体验；主题切换即时生效；布局种类丰富；无需网络连接，纯本地运行
- 不足
PNG 导出使用粗糙的 headless Chrome 截图；不能直接生成 .pptx 文件；没有 AI 图片生成能力

cat baoyu-skills/README.md

baoyu-skills

定位：AI 驱动的视觉内容生成工具集，包含四个核心 skill。

baoyu-slide-deck
17 个预设风格 + 4 维自定义（Texture × Mood × Typography × Density），9 步流程将内容转化为 AI 生成的幻灯片图片
baoyu-infographic
21 种布局类型 × 22 种视觉风格，自由组合生成信息图。关键词快捷如"高密度信息大图"自动匹配布局
baoyu-diagram
9 种 SVG 图类型（Architecture/Flowchart/Sequence/Structural 等），Dark 主题 8 种语义色彩，严格 z-order 分层规则
baoyu-imagine
统一的多 Provider 图片生成后端，支持 10 个 Provider（OpenAI/Google/DashScope/Z.AI/MiniMax 等），text-to-image + 参考图 + 批量
+ 整体优势
AI 图片生成质量高，风格多样；多 Provider 灵活切换；prompt 文件机制保证可复现性；SVG 架构图质量专业
- 整体不足
AI 生成幻灯片是图片，不可编辑文本；无交互式演示能力；生成速度慢（每张 10-30s）；无法精确控制文字排版和数据图表

cat academic-pptx-skill/README.md

academic-pptx-skill

定位：学术演示文稿的内容策略和结构规范，与 Anthropic 内置 PPTX skill 配合使用。

技术实现
依赖 pptxgenjs（Node.js PPTX 生成库），通过 JavaScript API 直接构建 .pptx
设计哲学
Communication-first（沟通优先），非 Design-forward（设计优先）
核心原则
Action Titles / Ghost Deck Test / 一页一观点 / 40 词上限 / 引用规范 / 以结论结束
Deck 架构
Title → Motivation → Research Question → Methods → Results → Discussion → Conclusions → References → Appendix
设计标准
白色背景，单一无衬线字体，最多 3 种颜色；标题 24-28pt / 正文 20pt / 图表标注 16-18pt / 引用 12-14pt
Slide Patterns
11 种标准页面模式，每种都有完整的 pptxgenjs 代码示例
+ 优势
学术演示最佳实践规范，方法论严谨；直接生成原生 .pptx 文件，文本和图表可编辑；内置 QA 流程保证质量
- 不足
仅限学术场景，风格单一（白底、无装饰）；无 AI 图片/插图生成能力；无交互演示能力

// 整合方案

目标：构建一个统一的演示制作系统，能够：

01 制作完整 PPT — 可交互网页版 + 可编辑 .pptx 文件

02 AI 插图 — 为幻灯片自动生成高质量插图、信息图

03 架构图 — 专业的 SVG 架构图/流程图/序列图

04 高质量渲染 — 用 CDP/Playwright 替代粗糙的 headless Chrome 截图

架构：内容分析层 → 结构规划层 → 风格决策层 → 渲染引擎层 → 导出引擎层

模块1-2：内容分析与渲染选择

// 模块1 — 内容分析与结构规划
采用 academic-pptx 的结构化论证框架（SCR/Funnel），扩展到非学术场景
采用 baoyu-slide-deck 的幻灯片计数启发式（基于文档长度）
保留信号自动检测（根据内容关键词匹配风格）
引入 Ghost Deck Test 作为大纲质量检查
// 模块2 — 渲染引擎选择器
文字+排版 → HTML（CSS 精确控制）
数据图表 → HTML 或 pptxgenjs
架构图/流程图 → SVG（baoyu-diagram）
插图/概念图 → AI（baoyu-imagine）
信息图 → AI（baoyu-infographic）
代码展示 → HTML（语法高亮）
封面/分隔页 → HTML 或 AI

混合渲染策略：单个 deck 内可混合使用多种引擎。例如封面 AI 背景 + HTML 文字覆盖，内容页 HTML 排版，架构图页嵌入 SVG。

import { chromium } from 'playwright';

async function renderSlides(htmlPath, outputDir) {
  const browser = await chromium.launch();
  const page = await browser.newPage({
    viewport: { width: 1920, height: 1080 },
    deviceScaleFactor: 2  // @2x Retina
  });
  await page.goto(`file://${htmlPath}`);
  await page.evaluate(() => document.fonts.ready);  // 精确字体等待
  const slideCount = await page.evaluate(
    () => document.querySelectorAll('.slide').length);
  // ... 逐页导航 → 动画检测 → 精确截图
}

cat ROADMAP.md

整合实施路线图

Phase 1 · 基础整合
1. Playwright 渲染器：替换 render.sh，新增 render-precise.ts（1-2天）
2. SVG 架构图嵌入：HTML 页面嵌入 baoyu-diagram SVG（0.5天）
3. AI 插图嵌入：使用 baoyu-imagine 生成图片（0.5天）
Phase 2 · PPTX 导出
4. 图片拼合导出：Playwright 截图 → merge-to-pptx，复用 baoyu-slide-deck 脚本（1天）
5. 原生 PPTX 生成：集成 pptxgenjs，复用 academic-pptx Slide Patterns，扩展到非学术风格（3-5天）
Phase 3 · 智能化
6. 内容自动分析：自动判断场景、推荐风格、规划页数（2-3天）
7. 引擎自动选择：根据每页内容类型自动选择最优渲染引擎（1-2天）
8. 统一 SKILL.md：编写整合后的 skill 定义文件（1天）
